# Scratch copies for build-config commands

Loaded by the orchestrate skill when a task runs a command that rewrites build config.

Commands that rewrite build config (`idf.py set-target`, `menuconfig`, `pio init`) run in a scratch copy of the tree at `/var/tmp/orchestrate-copy-<YYYYMMDD-HHMMSS>-<task>` (on disk, since /tmp is often RAM-backed; a safety hook may block `rm -rf` anywhere else, so keep copies only here and never under G; append its path to the ledger's Scratch copies line), never the shared one. You create it, without `.git` (so nothing run inside can move the real HEAD or index) and without build output: `mkdir -p <copy> && tar -C <R> --anchored --exclude=./.git --exclude=./build --exclude=./.pio --exclude=./node_modules --exclude=./.venv --exclude=./target -cf - . | tar -C <copy> -xf -` (anchored, so a nested `src/build/` is kept; a Check that needs `.venv` cannot use a copy). Create it after the task's dependencies are marked done. The worker edits files in R, so that task's Check starts by syncing its Files over, from Repo: `cd <R> && cp -f --parents <repo-relative Files and Tests> <copy>/ && cd <copy> && <build command>` (`--parents` creates missing dirs for new files; a file the task deletes needs an explicit `rm -f <copy>/<file>`); your own re-run of that Check then syncs the same way. Delete the copy with `rm -rf <copy>` after the task. A Check that needs one goes to a worker (read-only agents cannot create files outside their scratchpad), and you delete the copy after the task (workers cannot run `rm -r`).
